# smll v0.6.0 — agent-first defaults

**Breaking change.** smll is now lossy by default.

In v0.5, `SMLL_COMPACT=1` opted *in* to lossy compaction. In v0.6, lossy is
the default for every supported command. Set `SMLL_LOSSLESS=1` to bypass all
filters and pass raw child output through byte-identically.

## Migration

- `SMLL_COMPACT=1` — delete it from your shell rc. Silently ignored in v0.6.
- `SMLL_COMPACT=0` (or unset, relying on lossless default) — set
  `SMLL_LOSSLESS=1` instead.
- No other wrapper-mode contract changed. Commands, flags, exit codes, and
  stream separation are unchanged.

## New filters

| command | reduction | notes |
|---|---:|---|
| `find` / `find -ls` | 69% | strips GNU/BSD inode+mode+user+group+size+date columns; keeps paths |
| `du` / `du -sh` | 0% bytes | 2-sig-fig rounding + sort (wins via digit normalization, not bytes) |
| `curl -v` / `-vvv` | 75% | drops TLS handshake chatter + PEM certs; keeps request/response headers + body |
| `make`, `cargo build`, `go build` | 97–99% | collapses per-target progress to a count; preserves every warning/error |

## New fallback: 64 KiB-gated generic compactor

Any unknown command whose stdout exceeds 64 KiB now runs through a generic
streaming pipeline: ANSI strip → trailing-whitespace trim → consecutive-blank
collapse → consecutive-identical-line RLE.

Measured reductions on realistic fixtures (pip install, cargo build -vv,
journalctl, ps auxww): 40–99%. Short outputs pass through untouched.

## Binary size

- v0.5: 117848 B (under 150 KiB cap)
- v0.6: 243224 B (under 256 KiB cap)

Cap raised to absorb four new bespoke filters plus the generic compactor.
Still under 256 KiB, still `ReleaseSmall` + strip, still zero runtime deps.

## Agent-first design rationale

smll's job is feeding coding agents. Agents don't care about TLS handshake
banners, progress bars, or 500 identical `Compiling` lines — they care about
the next actionable fact. Flipping lossy-by-default removes one configuration
step between smll being installed and smll being useful in an agent loop.

The `SMLL_LOSSLESS=1` escape hatch is a first-class contract, not a
deprecation fallback. If you alias `smll` over raw tools for human use, set
it in your shell profile and everything behaves like v0.5-lossless.
